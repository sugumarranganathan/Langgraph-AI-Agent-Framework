|   **1** | What is LangGraph? What problem does it aim to solve compared to a simple linear chain of LLM calls?                                       | LangGraph is a graph-based orchestration framework for LLM workflows. It solves the limitation of linear chains by supporting branching, looping, conditional logic, and shared state for dynamic AI pipelines. |
|   **2** | What are the core concepts of a LangGraph workflow (e.g., nodes, edges, state)?                                                            | **Nodes** → Units of work (LLM calls, tools, functions). **Edges** → Define data flow between nodes. **State/Context** → Shared memory passed across nodes.                                                     |
|   **3** | Describe how a "node" functions in a LangGraph graph.                                                                                      | A node performs a single operation such as an LLM call, API request, or function execution, then sends its output to the next node.                                                                             |
|   **4** | Describe how an "edge" functions in a LangGraph graph.                                                                                     | An edge controls how outputs from one node become inputs for another, defining the graph's execution and data flow.                                                                                             |
|   **5** | How is "state" or "context" managed in LangGraph?                                                                                          | LangGraph maintains a shared state object that all nodes can read and update, enabling persistent memory throughout the workflow.                                                                               |
|   **6** | Give a simple example: build a LangGraph that takes user input, does an LLM call, then a function call. What nodes/edges would you define? | **Nodes:** Input Node → LLM Node → Function Node. **Edges:** Input → LLM → Function.                                                                                                                            |
|   **7** | What are some typical use cases where you'd prefer LangGraph over simpler workflows?                                                       | RAG pipelines, chatbots with memory, multi-step reasoning agents, automated AI workflows, document summarization, and data processing.                                                                          |
|   **8** | How do you handle branching logic in LangGraph?                                                                                            | Use conditional edges where a node's output determines the next node (e.g., success → summary node, failure → retry node).                                                                                      |
|   **9** | What is the difference between synchronous vs asynchronous node execution?                                                                 | **Synchronous:** Executes one node at a time. **Asynchronous:** Runs independent nodes in parallel for better performance.                                                                                      |
|  **10** | How do you define reusable graph components or subgraphs?                                                                                  | Group related nodes into reusable subgraphs or templates that can be shared across workflows.                                                                                                                   |
|  **11** | How do you integrate custom functions/tools into LangGraph nodes?                                                                          | Wrap external functions or APIs as custom nodes with defined inputs and outputs, then connect them using edges.                                                                                                 |
|  **12** | How would you monitor execution of a LangGraph graph?                                                                                      | Use `.visualize()` or `.to_dot()` for visualization, and enable logging, metrics, or tracing to monitor execution, errors, and performance.                                                                     |
|  **13** | What are the benefits of using LangGraph in production?                                                                                    | Modular and scalable design, easier debugging, branching support, reusable components, improved state management, and observability.                                                                            |
|  **14** | What are the limitations of LangGraph?                                                                                                     | Higher setup complexity, steeper learning curve, more difficult debugging for large graphs, careful state management required, and overhead for simple tasks.                                                   |
|  **15** | How would you explain LangGraph to a non-technical stakeholder?                                                                            | LangGraph is like a flowchart for AI workflows that connects LLMs, tools, and data sources to automate complex reasoning tasks.                                                                                 |
|  **16** | How do you handle error handling or retry logic in LangGraph nodes?                                                                        | Use retry policies, error-handling nodes, catch exceptions, retry failed nodes, or redirect to fallback paths.                                                                                                  |
|  **17** | How do you implement caching of outputs from nodes?                                                                                        | Store previous inputs and outputs in a cache (e.g., Redis or local DB). Return cached results for repeated inputs.                                                                                              |
|  **18** | How would you design a LangGraph workflow for batch processing?                                                                            | Use batch-processing nodes with parallel edges so independent batches run asynchronously.                                                                                                                       |
|  **19** | How do you integrate vector-store retrieval (RAG) into LangGraph?                                                                          | **Nodes:** Input → Retrieval → LLM. The Retrieval node fetches documents from a vector store before the LLM generates the answer.                                                                               |
|  **20** | How would you support multi-turn conversation with memory?                                                                                 | Store chat history in persistent state. Update it each turn so the LLM retains conversation context.                                                                                                            |
|  **21** | How do you guard against prompt injection or malicious input?                                                                              | Add input validation, sanitization, filtering nodes, and guardrails or moderation APIs.                                                                                                                         |
|  **22** | How do you manage secrets/API keys in LangGraph?                                                                                           | Store keys in environment variables or secret managers. Never hardcode credentials.                                                                                                                             |
|  **23** | How would you version control and deploy LangGraph graphs?                                                                                 | Use Git, store graphs as JSON/YAML or Python modules, and deploy via CI/CD pipelines or Docker containers.                                                                                                      |
|  **24** | How would you measure workflow performance?                                                                                                | Add logging and metrics for latency, token usage, and cost. Optimize using caching, parallel execution, or prompt simplification.                                                                               |
|  **25** | How would you debug a failing or stuck node?                                                                                               | Enable debug logging, inspect inputs/outputs, use visualization tools, and analyze state and error stacks.                                                                                                      |
|  **26** | How do you handle state persistence across graph executions?                                                                               | Persist state objects in a database or file store, reload them, and resume execution from the last completed node.                                                                                              |
|  **27** | How do you implement conditional branching based on upstream output?                                                                       | Use if-else conditional edges that route execution to different nodes based on output conditions.                                                                                                               |
|  **28** | How do you implement loops or iterative workflows?                                                                                         | Define loop edges that reroute execution until a stopping condition is met while tracking iterations to avoid infinite loops.                                                                                   |
